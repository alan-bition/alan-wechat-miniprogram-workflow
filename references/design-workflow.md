# 设计协作与原生小程序适配

本参考文件用于 UI 设计、页面改版和按稿实现。它把可选的设计 Skill 接入微信原生小程序流程，同时保留用户已经确认的 PRD、视觉稿、技术栈和交付边界。

## 何时读取

- 已有页面需要审查或改版时。
- 需要从设计规范整理令牌、组件状态和 WXSS 规则时。
- 已确认视觉稿，需要按稿实现并做视觉对照时。

纯后端修复、接口排查或只更新文案时，不必为了形式启动完整设计链路。

## 五个 Skill 的职责

| 阶段 | 可选 Skill | 输入 | 输出 |
| --- | --- | --- | --- |
| 体验审查 | `audit` 或 `product-design:audit` | 当前页面、原型、截图、可复现路径 | 带证据的逐屏问题、严重程度、可访问性风险和证据限制 |
| 改版方案 | `ui-ux-pro-max` | PRD、审查结果、品牌和平台约束 | 页面层级、交互状态、视觉方向、响应式与可用性建议 |
| 设计令牌 | `design-system` | 设计规范、确认稿、品牌参数 | 基础→语义→组件三层令牌、组件状态和参数映射 |
| 样式实现 | `ui-styling` | 令牌、组件规格、原生平台限制 | 可转换为 WXSS 和原生组件的样式结构与状态规则 |
| 按稿实现 | `image-to-code` 或 `product-design:image-to-code` | 明确选定的截图/高保真稿、令牌、素材 | 与视觉目标一致的页面实现和设计 QA 输入 |

五个 Skill 的结果要合并到同一份设计规范和验收记录中。不要分别生成互相矛盾的颜色、字体、间距或组件规则。

## 三种入口

### 已有页面改版

1. 先用审查流程捕获当前页面和关键状态。
2. 区分截图能证明的视觉问题与必须通过点击、原型或真机验证的交互问题。
3. 用 `ui-ux-pro-max` 形成改版方案，先确认登录、首页、核心表单等代表页面。
4. 用 `design-system` 固化确认后的颜色、字体、间距、组件状态和动效。
5. 用 `ui-styling` 映射到 WXSS，再用 `image-to-code` 按确认稿实现。
6. 用相同尺寸、数据和状态截图对照，修复 P0/P1/P2 差异。

### 从零开发

先完成 PRD 和可点击 HTML 原型，再开始审查。没有可访问页面时，不要编造审查截图或审查结论；可以审查原型状态和信息架构。视觉方向先提交代表页面和必要错误态，得到确认后扩展全量页面。

### 局部修复

只启动与问题相关的环节。例如筛选项文字居中可直接检查设计令牌和 WXSS；若修复改变页面层级或状态，再补充审查和视觉 QA。后端或数据库修复不强制调用 UI Skill。

## 依赖查找与回退

按当前环境中的 Skill 名称查找，不写入个人绝对路径：

1. 审查优先查找 `product-design:audit`，也接受 `audit`。
2. 按稿实现优先查找 `product-design:image-to-code`，也接受 `image-to-code`。
3. 其他三个按 `ui-ux-pro-max`、`design-system`、`ui-styling` 查找。

每次记录四种状态之一：已使用、未安装、依赖不完整、按内置流程回退。缺少可选 Skill 时，使用本工作流已有的审查、令牌、组件和视觉检查方法继续；不得把回退写成已经调用了外部 Skill。

如果用户明确说某个 Skill 必须使用，且该 Skill 缺失或无法读取，则暂停依赖它的阶段，说明缺口，同时继续完成不依赖它的准备工作。

## 原生小程序适配规则

- 小程序实现以 WXML、WXSS、页面/组件 TypeScript 和现有工程构建方式为准。
- `ui-styling` 中的 shadcn/ui、Radix、Tailwind、React 示例只作为设计原则参考；不要因此引入 React、Tailwind、GSAP 或重建项目。
- 将令牌转换为 WXSS 变量或集中样式类；保持页面、组件和状态使用同一组值。
- 优先使用微信原生 `button`、`input`、`scroll-view`、`form` 等控件，补充可读的提示、禁用和错误状态。
- 主要点击区至少 44×44px；安全区、键盘、自然滚动和大字号必须在原生页面或真机检查。
- 设计图中的图片、纹理和图标要登记来源、用途、尺寸、裁剪与授权。复用已授权品牌素材，不擅自重绘或重新生成品牌标识。
- `image-to-code` 只有在存在明确选定视觉目标时才启动；原型截图或高保真稿是参考，不是原生运行证据。

## 设计 QA 交付

对照稿和实现必须使用相同页面、状态、数据、视口和字号。报告至少包含：

- 参考稿与实现的版本或文件标识。
- 页面、状态、尺寸、数据和截图路径。
- P0/P1/P2/P3 差异、处理方式和复核结果。
- 截图无法验证的交互、微信能力和真机限制。

没有有效参考截图、实现截图或运行环境时，写明“阻塞”或“未执行”，不能用构建成功、接口健康或 HTML 预览代替原生视觉验收。
