# 微信小程序问题排查

以下来自原生小程序实践。微信平台政策会变化，执行时核对账号主体、基础库和当日官方文档；案例方案不是平台强制标准。

## 登录不是获取手机号

`wx.login` 获取临时 code，后端通过 code2Session 换取微信身份后建立自己的业务会话。获取手机号是另一项能力，涉及额外条件及用户授权。不能因为按钮写“一键登录”就默认必须收集手机号。

协议勾选默认不选中；失败区分用户拒绝、网络、合法域名、TLS、超时、会话过期与服务器错误。不得在日志或分享图中保存 code、session_key、完整令牌或个人资料。

## 域名与真机

request 合法域名填写 HTTPS 域名，不带 `/api` 路径；客户端 API_BASE 可以包含 `/api`。只配置实际使用的请求类别。平台保存后核对 AppID，刷新开发者工具项目域名信息，重新编译，再使用正常校验的真机环境验证。

远程真机调试可能有独立的“不校验合法域名”设置。调试成功不能代替普通体验版；以用户通过普通体验码走通实际登录作为该层级的证据。网络可通或返回 401，只能证明请求到了服务，并不证明新用户登录成功。

配置刷新、重选体验版后恢复时，如无法区分配置传播和客户端缓存，只记录“恢复操作与结果”，不要武断认定唯一根因。

## TypeScript 与上传包

修改 TS 后重新生成 JS，确认上传的实际文件来自本次源码。单测优先解析源 TS，避免同目录生成 JS 形成另一份模块实例。不要复制本机私有项目配置进上传目录。

## 前后端版本不同步

新前端依赖新增响应字段时，优先部署兼容的新后端并验证该字段，再发布前端。接口兼容降级须明确设计；不要把“字段缺失”默默当成“没有业务数据”掩盖部署错误。

排查顺序：前端实际请求 → 响应契约 → 日期/时区/过滤规则 → 正在运行的服务版本 → 渲染。`/health` 成功不代表业务契约匹配。

## 计时、统计和并发

计时每秒显示可以在客户端根据服务器基准递增，协同请求按业务需要独立刷新；页面隐藏、销毁、结束时清理计时器。避免每次同步造成回跳或倍速。

统计先约定业务时区、日期范围、删除过滤、逐笔还是分桶、排序与跨日归属。类似“每个时段”需明确是每笔还是整点汇总。同一分钟多笔不应无意合并。秒转分钟的取整规则要确认，显示取整不应破坏原始统计精度。

数据库事务、唯一约束与提交意图标识共同处理重复保存或并发开始计时；不能仅靠前端禁用按钮。

## 订阅提醒

一次性订阅和长期订阅不同，能力取决于账号类别和模板。按钮禁用状态、防重复请求、用户拒绝/取消提示需明确；接受结果按当前模板 ID 判断。后端状态不能被解释成永久微信授权，授权消费和再次订阅要按业务设计及官方行为处理。

实际消息投递测试需目标接收者与通知测试的授权；模拟接受状态不能证明微信投递成功。

## 邀请与普通分享

普通分享只携带公开参数与固定封面，不能默认截图含私人数据的页面。邀请按钮使用有效邀请参数；菜单转发不应生成空邀请码。邀请权限与一次性消费由后端保证。

朋友圈 `onShareTimeline` 分享当前页面，参数由 query 控制。使用场景值 1154 识别单页模式：首帧和 onShow 展示公开介绍，不触发登录跳转、业务查询或轮询；返回完整小程序按当前场景恢复。开发工具注入场景只能证明应用分支，不能证明微信原生容器行为。

## 隐私指引版本

核对当前开发版本的代码能力识别及隐私指引，不只修改现网旧版。准确区分信息类型、处理目的、联系方式、保存期限与第三方 SDK。删除未使用条目也需核实新版本代码，不为通过审核虚报权限。

更新并上传代码后再刷新识别结果。进入提审信息页不等于提交审核；隐私承诺、扫码或验证应遵循当前平台/工具要求。

## 数据预拉取 6000100

`unbind download url` 可能来自启用了预拉取调试却未绑定数据源。先查项目私有配置和是否实际使用预拉取 API。未使用该可选能力时关闭本地预拉取调试；不要关闭 request 域名或 TLS 校验来掩盖错误。

官方文档对主体与数据来源有条件限制；准备启用时重新核验，不能把普通业务 API 地址直接当作已经配置成功的数据预拉取来源。
