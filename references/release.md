# 预览与版本交付

## 先确认当前动作范围

| 动作 | 完成证据 |
| --- | --- |
| 本地构建 | 对应源码的生成文件与构建结果 |
| 预览 | 开发者工具生成二维码；设备打开对应包 |
| 上传开发版 | 工具上传成功，后台 AppID/版本/时间一致 |
| 选为体验版 | 后台标记、入口页、体验成员与体验码核对 |
| 提交审核 | 用户授权及后台审核版本、状态 |
| 正式发布 | 用户授权及后台线上版本、发布结果 |

版本号从当前后台与项目记录确定，不固定复制示例。尊重同一会话已经给出的授权，不重复确认；未包含的后续阶段不能擅自执行。

## 上传前

1. 记录源码版本、前端候选号、后端镜像或提交、迁移版本、生成时间和变更说明。
2. 若本次包含页面改版，确认设计 QA 已完成或明确记录为未执行/阻塞；未完成视觉证据不能写成已通过。
3. 发现项目实际脚本；不要直接执行不存在的示例 npm 命令。运行类型检查、相关测试与生产构建。
4. 确认最新 TS 已生成 JS。上传包与源码仓库是不同清单：源码库可以排除生成 JS；运行包必须包含运行所需 JS/WXML/WXSS/JSON 和素材。
5. 检查 API_BASE、正式微信模式、当前有效的订阅模板、AppID 与基础库；密钥不能进前端。
6. 排除私有项目配置、`.env`、凭证、日志、数据库、设计文档、测试报告及无关素材。不要改写源码本身来“排除”文件，优先使用受控上传目录或工具打包规则。
7. 生产目标开启正常域名和 HTTPS 校验。本地 HTTP 的专用配置不能混入候选包。
8. 核验正式 API 的业务字段、鉴权与错误行为，不止检查健康接口。无需制造真实用户数据，优先使用授权的测试身份或脱敏聚合检查。

## 后端联调前提

本机 `127.0.0.1` 不等于手机可访问服务。选择获准的局域网测试或正式 HTTPS 服务，记录范围。新增接口契约先部署兼容后端，再上传依赖它的前端。

云端部署是单独动作：确认服务器架构，使用有版本的镜像/构建产物；生产密钥单独配置；只运行所需迁移，不 seed；涉及真实数据升级前备份并验证恢复；预留回滚版本。健康失败按既定方案回滚，不把用户数据清空作为恢复手段。

## 微信后台与隐私

核对主体类别、服务类目、实际 API 能力、域名、订阅模板和当前开发版本隐私指引。平台“保存”“扫码确认”“提交”是不同状态，以实际界面为证据。

资料应由实际功能和用户提供的信息生成，不填猜测的运营者实名、邮箱、保存期限或权限。隐私承诺和管理员验证按平台及工具规则处理。

## 预览、上传与体验

调用已安装官方 CLI 前阅读该版本帮助；使用项目绝对路径和明确版本，妥善引用 shell 参数。不要在脚本中保存扫码凭证或私钥。遇到工具登录、设备扫码限制时清楚说明需要用户完成哪一步。

预览仅是临时开发入口。上传后必须检查微信后台中的 AppID、版本号、提交时间和备注；需要体验版时再选择正确入口并核验标记。使用普通体验码测试，不依赖绕过校验的调试会话。
