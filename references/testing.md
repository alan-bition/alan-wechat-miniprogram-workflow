# 验证与证据规范

## 分层验证

| 层级 | 应证明什么 | 不能代替什么 |
| --- | --- | --- |
| 类型/源码/构建 | 类型、路由、素材、格式、产物正确 | 业务和微信客户端行为 |
| 单元与接口测试 | 规则、权限、校验、异常分支 | 原生页面实际点击 |
| 真实数据库测试 | 事务、并发、约束、迁移和持久化 | 生产环境已部署 |
| 原生 UI 自动化 | 实际 WXML 状态、布局、路由和数据联动 | 真实微信授权与投递 |
| 真机调试 | 指定调试配置下的设备行为 | 正常体验版环境 |
| 普通体验版 | 指定候选版本的真实使用流程 | 未执行功能或正式版表现 |

## 环境隔离

开发库与测试库用独立目标。脚本先确认主机、端口、库名或等价隔离条件，再允许测试清理。目标未知、远程地址未经授权时停止破坏性准备；不要用另一个看似可用的库替代。

虚构种子能重建固定场景，生产禁止 seed。数据库卷清理与服务停止不同，不把删卷当成普通重启。

## 用例选择

按需求测试行为，而不是复刻实现。覆盖有风险的权限、并发、重复提交、迟到响应、跨日统计、失败保留输入和草稿隔离。为局部修复添加能复现旧问题的回归；低影响静态文案不必写机械快照测试。

示例：创建 08:30/100mL 和 08:30/120mL 两笔，预期独立展示、总量 220；删除一笔后明细和总量一致；切换日期无串入；周汇总不变。数值来自业务规则，不从被测实现计算预期。

## 视觉验收

设计流程的证据分为两份：页面审查记录说明当前问题和证据限制；设计 QA 说明确认稿与原生实现的差异和复核结果。两者都要标明实际使用的 Skill、内置回退、源码标识、页面状态、数据、宽度和字号。

1. 对齐参考稿与实现的版本、数据、宽度、字号、状态。
2. 默认检查 320/375/430px、字号 1/1.3/1.6，按产品设备范围调整并记录。
3. 检查横向溢出、文字截断、自然滚动、字段错误、键盘遮挡、底部安全区和点击区域。
4. 正文对比度至少 4.5:1；主要操作区至少 44×44 CSS px，相邻操作建议保留至少 8px。
5. 375px 设计基准下 1px=2rpx；其他宽度按 `rpx = px × 750 / 设计基准宽度` 换算。字体和触控目标不能只靠比例缩放保证可读性。
6. 字号状态注入标为“注入”，真实系统字号切换标为“系统设置”；分别验证，不混淆。
7. 工具不可用时列为未执行，不能以重绘截图或 DOM 静态检查冒充原生结果。

## 报告字段

记录执行时间、源码提交或内容摘要、环境版本、API/数据库环境代号、用例编号、预期、实际、状态、证据、限制。日志去除鉴权头、隐私数据及服务器秘密。

完整通过、部分通过、未执行是不同状态。报告只覆盖本次实际执行范围；旧结果可引用为历史，不计入当前通过数。一个测试带多个需求编号，不代表这些需求全部分支均覆盖。

## 修复闭环

复现 → 定位证据 → 最小变更 → 针对性测试 → 必要回归 → 更新报告。若失败来自工具或测试环境，修正环境并保留失败原因；不要删掉断言换取成功。
